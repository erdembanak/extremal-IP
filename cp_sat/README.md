CP-SAT version of the extremal-IP graph model

This ports the binary graph formulation in
[extremal-IP](https://github.com/erdembanak/extremal-IP/blob/570d6726c31cc976e864e001b5acc8c2ee561029/main/base-runs.cpp)
to OR-Tools CP-SAT. Python builds the model; the search runs in the compiled
C++ solver. No CPLEX installation or license is needed.

The full Earth–Moon candidate enumeration is now complete: one class at 58
edges and three at 57 edges, replicated with a second encoding. See
[RESULTS.md](RESULTS.md) for the exact scope, explicit graphs, and limitations.

For the broader **17-vertex catalogue without independence or factor-criticality
constraints**, see [UNRESTRICTED.md](UNRESTRICTED.md): two classes at 58 edges
and 21 at 57 edges. It has separate code, run directories, and graph exports.

Create an environment at `.tools/cp-sat-venv`
from the repository root (Python 3.10 or a compatible newer version):

```bash
python -m venv .tools/cp-sat-venv
.tools/cp-sat-venv/bin/python -m pip install -r cp_sat/requirements.txt
```

`pynauty` builds a bundled nauty library and needs a C compiler. The pinned
versions in requirements.txt are the versions used for the initial checks.

**Model and scope**

- One Boolean x_ij for each unordered pair of vertices.
- Triangle constraints x_ij+x_ik+x_jk ≤ 2.
- Degree bounds deg(v) ≤ d.
- Either maximize the number of edges (`--optimize`) or fix it for enumeration.
- Optional α ≤ a: every (a+1)-set contains an edge.
- Optional factor-criticality: after each vertex deletion, existential binary
  matching variables specify a perfect matching using graph edges.
- Optional exact degree multiset, indexed by `--degree-pattern`.

The model is for graphs of the specified order. With n=2m+1, the matching upper
bound ν≤m is automatic. It does not enumerate arbitrary-order graphs satisfying
the matching constraint. At n=17,d=7,e≥57, the known f_Delta(7,7)=50 also forces
ν=8. The checker computes the matching number explicitly anyway.

The default model sorts degrees in nonincreasing vertex order. Every
isomorphism class has such a labeling. Use `--no-degree-order` when testing
enumeration of every labeled graph.

**Nauty and solution exclusions**

Each returned graph is independently checked, assigned a nauty canonical
certificate through `pynauty`, and written to `solutions.jsonl`.
`new_isomorphism: true` marks the first representative of its class.

After finding an edge set E, the program adds sum(x_e for e in E) ≤ |E|−1.
Since the total edge count is fixed, this excludes precisely that edge
assignment, regardless of the auxiliary matching witnesses.

`--relabel-blocks 128` also blocks up to 128 additional isomorphic copies.
They are generated by vertex transpositions within equal-degree classes.
These cuts are safe because the saved graph already represents their entire
isomorphism class. They do not exclude unrelated graphs. This is bounded
sampling of an isomorphism orbit, not full isomorphism-free generation;
duplicate classes can still be returned and are identified by nauty.

The old CPLEX orbital-branching callback is not reused. CP-SAT uses its own
search and symmetry machinery. Nauty currently handles output canonicalization;
the additional relabeling cuts are explicit model constraints. This port does
not claim to reproduce the original callback's search performance.

`--row-lex` adds lexicographic adjacency-row comparisons for pairs of equal-degree
vertices. These compare each graph against a relabeling obtained by swapping
that pair. Every degree-preserving isomorphism orbit has a lexicographically
least upper-triangular adjacency vector, which satisfies all these comparisons.
Thus the constraints preserve a representative of every class. Their effect on
complete small-graph catalogues is covered by the tests. They substantially
strengthen degree sorting without relying on the CPLEX callback.

**Run the Earth–Moon candidate search**

List all possible degree multisets. Indices are zero-based and printed in full:

```bash
.tools/cp-sat-venv/bin/python cp_sat/enumerate_graphs.py --edges 58 --list-patterns
.tools/cp-sat-venv/bin/python cp_sat/enumerate_graphs.py --edges 57 --list-patterns
```

There are three degree patterns for 58 edges and seven for 57 edges. Some
patterns may be impossible after the other restrictions. No pattern is
discarded merely because an optimization run already attained 58 elsewhere.

For a one-minute pilot on all degree patterns at 58 edges:

```bash
.tools/cp-sat-venv/bin/python cp_sat/enumerate_graphs.py \
  --edges 58 --alpha-max 7 --factor-critical \
  --workers 4 --time-limit 60 --relabel-blocks 128 \
  --output cp_sat/runs/earthmoon-58
```

To split the work into degree cases, add `--degree-pattern 0`, `1`, or `2`,
and use a different output directory for each. For the 57-edge layer use
`--edges 57`; its pattern indices are 0 through 6.

To resume for another hour, repeat the SAME model and relabeling options,
adding `--resume` and increasing the time budget:

```bash
.tools/cp-sat-venv/bin/python cp_sat/enumerate_graphs.py \
  --edges 58 --alpha-max 7 --factor-critical \
  --workers 4 --time-limit 3600 --relabel-blocks 128 \
  --output cp_sat/runs/earthmoon-58 --resume
```

`--max-solutions N` optionally limits how many new edge assignments a run
saves, including isomorphic duplicates. It does not limit the unique count.
Both budgets apply to the current invocation. Graph checking can slightly
extend the wall-clock limit. Resume rebuilds all exclusion constraints;
it does not restore CP-SAT's internal learned clauses or search tree.

For the unrestricted 17-vertex catalogue, omit `--alpha-max 7` and, if desired,
`--factor-critical`. Those options are filters and change the catalogue's scope.

**Optimization mode**

```bash
.tools/cp-sat-venv/bin/python cp_sat/enumerate_graphs.py \
  --vertices 17 --degree 7 --optimize --workers 4 --time-limit 60 \
  --output cp_sat/runs/optimize-7-8
```

This performs a single optimization solve and records its best returned graph
and objective bound. An optimal result is not an enumeration of all optima.
Resume and degree-pattern partitioning apply only to fixed-edge enumeration.

**Full enumeration of both layers**

```bash
.tools/cp-sat-venv/bin/python cp_sat/full_enumeration.py --round-seconds 120
```

This schedules all ten degree cases with α≤7 and factor-criticality, using
row-lex symmetry constraints, nauty canonicalization, and additional relabeling
exclusions. By default it runs three jobs with three solver workers each.
Timed-out cases resume in successive rounds with increasing budgets, up to
one hour per case per round. A new seed is used for each round. The supervisor
continues until all ten cases are complete. Use `--max-rounds 1` for a bounded
pass. Restarting the same command resumes saved cases; it does not restart
cases whose summaries already show completion.

Results live under `cp_sat/runs/full/`: per-case logs and checkpoints, aggregate
`status.json`, and `catalogue-57.json` / `catalogue-58.json`, each retaining one
representative per nauty class found so far. The aggregate files update after
each case finishes a round; individual `solutions.jsonl` files update as graphs
are found. Until the aggregate status says complete, the catalogues are partial.
The scope is the Earth–Moon candidate family, not every unrestricted extremizer.

**Reading the output**

- `manifest.json`: exact mathematical filters, versions, source hash, and
  isomorphic-exclusion settings.
- `solutions.jsonl`: all graphs returned so far, explicit edges, independently
  computed properties, canonical certificates, and first-representative flags.
- `summary.json`: counts and the last solver status. In enumeration mode,
  `complete: true` appears only after the residual model returns `INFEASIBLE`.

An optimal *feasibility* response means one graph was found; it does not mean
enumeration is complete. Timeouts, unknown status, solution limits, and
interruptions leave `complete: false`. A complete degree-pattern run covers
only that pattern; complete coverage of a layer needs every pattern, or a
complete run without a pattern restriction.

Checkpoints reject changed model/code/package versions and corrupt records.
New runs refuse to overwrite nonempty directories. Use one process per output
directory. On interruption, saved JSONL rows are flushed individually; a
truncated final record must be resolved before resume, which fails closed.

Completion relies on CP-SAT's infeasibility result and the tested encoding.
The program does not produce a separately checkable formal UNSAT proof.
It also does not test biplanarity of the cones.

**Validation**

```bash
.tools/cp-sat-venv/bin/python -m unittest discover -s cp_sat -v
```

The tests compare labeled enumeration with brute force on small graphs,
compare complete isomorphism-class sets with/without symmetry restrictions,
check all twelve labeled five-cycles with factor-critical matching witnesses,
and exercise infeasibility, optimization, restart, timeouts, and corrupt
checkpoints. Nauty certificates are checked across a complete small relabeling
orbit. Every returned graph is additionally checked with exact bitset
independence computation and NetworkX's blossom matching algorithm.
The tests also fix the model to the 17-vertex blowup and B_(7,8) as positive
and negative controls for the independence restriction. See
[VALIDATION.md](VALIDATION.md) for the initial test and solver-pilot results.

CP-SAT status semantics are documented in the
[official solver guide](https://developers.google.com/optimization/cp/cp_solver).
